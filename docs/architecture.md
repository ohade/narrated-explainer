# Architecture

Narrated Explainer turns any material into one self-contained HTML file: an animated SVG story
with spoken narration, sound effects, captions and playback controls. It runs offline. The voice
is recorded at build time with local open-source models and embedded in the file, so the page
makes no network call when someone reads it.

This file is the contract between the parts. Each part may be rebuilt as long as it keeps this
contract.

## The parts

| Part | Language | Lives in | Job |
|---|---|---|---|
| Skill | Markdown | `skills/narrated-explainer/` | Teaches an agent to storyboard material and write a story |
| Story | JSON + JS | any folder, e.g. `examples/deadline-race/` | One explainer: its text (`story.json`) and its drawing (`scene.js`) |
| Runtime | JS + CSS | `src/narrated_explainer/runtime/` | The player, the drawing kit and the sound effects, inlined into every build |
| Build tool | Python | `src/narrated_explainer/` | The `explainer` command: narrate, build, check, snapshots, video |
| Setup | sh / PowerShell | `setup.sh`, `setup.ps1` | Installs uv, Python, dependencies, models and the skill |

## Story folder

```
my-story/
  story.json        # all visible and spoken text, timing and modes (authored)
  scene.js          # the pure model and the drawing (authored)
  narration/        # generated by `explainer narrate`: manifest.json and one MP3 per caption
  dist/             # generated by `explainer build`: <id>.html, snapshots/, video files
```

### story.json

```json
{
  "id": "deadline-race",
  "title": "Racing the deadline",
  "description": "Optional one-paragraph intro shown above the figure.",
  "lang": "en",
  "voice": { "engine": "kokoro", "voice": "am_michael", "speed": 1.0 },
  "pronounce": { "API": "A P I" },
  "modes": [ { "id": "before", "label": "Before" }, { "id": "after", "label": "After" } ],
  "timing": { "end": 320, "unit": "ms", "realMsPerUnit": 30, "holdMs": 1600, "speeds": [0.5, 1] },
  "atRest": { "mode": "before", "t": 320, "caption": "Press Play to watch the request from the start." },
  "intro": [
    { "id": "intro-1", "caption": "The App sets its stopwatch.", "sfx": "wind", "holdMs": 2000 }
  ],
  "moments": [
    { "id": "send", "t": 0, "caption": "The App sends the request.", "sfx": "click" },
    { "id": "late", "t": 201, "modes": ["before"], "caption": "B could run long after the deadline." }
  ],
  "labels": { "play": "Play" }
}
```

Rules, enforced by `explainer check`:

- `id` fields match `^[a-z0-9][a-z0-9-]*$` and are unique across `intro` and `moments`.
- `modes` is optional. Without it the story has one mode, `"main"`, and no mode toggle is shown.
- A moment's `modes` lists the modes it belongs to; without it, the moment is in every mode.
- `t` is required on moments, absent on intro steps, and within `0..timing.end`.
- `caption` is the displayed text and, by default, the spoken text. `say` overrides what is
  spoken for that caption only. `pronounce` maps whole words to spoken forms for every caption.
- `sfx` names a cue from the sound-effect list below. `holdMs` overrides `timing.holdMs`.
- `labels` overrides control texts for other languages. Keys: `play`, `pause`, `restart`,
  `prev`, `next`, `voiceOn`, `voiceOff`, `soundOn`, `soundOff`, `speed`, `mode`, `transcript`,
  `fullscreen`.

### scene.js

A plain browser script with no imports. It registers one factory:

```js
NarratedExplainer.scene(function (story, kit) {
  function stateAt(mode, t) {          // pure: same input, same output; no DOM, no clock
    return { t, gateway: t < 200 ? 'busy' : 'working' };
  }
  let parts;
  return {
    stateAt,
    build(stage) {                     // called once; create SVG nodes with kit
      const svg = kit.svg(stage, '0 0 1200 600', 'System view');
      parts = { gateway: kit.box(svg, { x: 430, y: 50, w: 370, h: 240, label: 'Gateway' }) };
    },
    draw(state, ctx) {                 // called every frame; only reads state and ctx
      parts.gateway.setStatus(state.gateway, 'ink-2');
    },
  };
});
```

`ctx` holds:

| Field | Meaning |
|---|---|
| `mode`, `t` | Current mode id and story time |
| `at` | `{ kind, index, id }`, where `kind` is `rest`, `intro`, `moment` or `between` |
| `motion(ms)` | 0..1 progress of the motion that started when the player arrived at the current intro step or moment. It returns 1 when paused, at rest, after a step button, in reduced motion, and once `ms` has passed |
| `playing`, `reduced` | Booleans |
| `sfx(name)` | Plays a cue once per arrival; repeat calls in the same arrival do nothing. Live playback only: snapshots and videos include only the `sfx` cues in `story.json`, so put every cue that matters there |

During intro steps the player passes `stateAt(mode, 0)`. A scene reads `ctx.at` to draw the
intro differently.

## Runtime

Three scripts and one stylesheet, inlined in this order: `kit.js`, `sfx.js`, `player.js`,
`player.css`. Together they define `window.NarratedExplainer`.

### Player behaviour

The player is split into a pure controller (positions, clock, plan; testable in Node with no
DOM) and a view (controls, captions, audio, drawing calls).

- **Positions.** For a mode, the positions are the intro steps in order, then the moments of
  that mode sorted by `t`.
- **At rest.** On load the player draws `stateAt(atRest.mode, atRest.t)` with motion 1 and shows
  `atRest.caption`. It never plays on load and makes no sound before a click.
- **Play** from rest or **Restart** starts at the first intro step, or at `t = 0` without an
  intro. Play after a pause continues from where it stopped.
- **Arrival** at a position starts its motion clock, plays its narration clip and its `sfx`
  cue. The player leaves the position when both the hold time has passed and the clip has
  ended. A clip that never reports its end releases the hold after its duration plus 1500 ms,
  or after 12000 ms when the duration is unknown.
- **Between moments** story time advances by `speed / realMsPerUnit` units per real
  millisecond, and stops exactly on the next moment's `t`. After the last moment, time runs to
  `timing.end` and playback stops there.
- **Step buttons** stop playback and narration, move one position, draw it with motion 1 and
  speak its caption.
- **Mode switch** keeps `t` and stops the current clip. Playback continues if it was playing.
- **Reduced motion** (`prefers-reduced-motion: reduce`): Play moves from position to position
  every 2500 ms, or when the clip ends if that is later, with motion always 1.
- **Controls**, built by the player: mode toggle (two or more modes), Play/Pause, Restart,
  Previous, Next, speed toggle, Voice on/off with the voice name, Sound on/off, a progress bar
  with one clickable marker per position, Transcript (all captions of the mode; a click jumps
  there) and Fullscreen. The controls row is sticky; its `top` comes from `--nx-sticky-top`.
- **Keyboard**, while focus is inside the figure, or anywhere on a page with one player:
  Space or K play/pause, Left/Right previous/next, R restart, V voice, S sound, T transcript,
  F fullscreen, 1-9 select a mode.
- **Captions** sit in a `figcaption` with `aria-live="polite"`. When the clip has word timings
  and the voice is on, the current word is highlighted while the clip plays.

### Deterministic rendering (snapshots and video)

Each mounted player is pushed to `NarratedExplainer.players`. For tools, it exposes:

- `positions(mode)` returns `[{ kind, index, id, t, caption }]`.
- `goto(mode, index)` draws that position with motion 1 and its caption, and plays no audio.
- `plan(mode)` returns `{ duration, segments }` for playback at speed 1 with the voice on. Each
  segment is `{ kind: 'hold', start, end, at, clipId, sfx }` or
  `{ kind: 'travel', start, end, tFrom, tTo }`, in real milliseconds. A hold lasts
  `max(holdMs, clip duration + 300)`.
- `renderAt(mode, ms)` draws the frame at `ms` on that plan, with motion computed from plan time
  instead of the clock. It plays no audio.
- `soundtrack(mode)` resolves to `{ sampleRate, wavBase64 }`: narration clips and sound cues
  placed on the same plan, mixed with an `OfflineAudioContext`.

### kit.js

Pure helpers that also work in Node: `clamp01`, `lerp`, `ramp(t, from, to)`, `along(points, p)`
and `ease.inOut`, `ease.out`, `ease.in`, `ease.outBack`.

SVG helpers that return small handles with setters, so `draw` only changes attributes:

| Helper | Draws |
|---|---|
| `svg(stage, viewBox, label)` | A responsive SVG with an accessible label |
| `el(parent, tag, attrs)`, `text(parent, x, y, str, opts)` | Raw nodes; text has an optional page-colour halo and picks a readable colour for the fill it sits on |
| `box` | Rounded box with a title and a status line |
| `arrow` | Line or arrow, optionally dashed, with a draw-on progress |
| `token` | A labelled chip that moves along a path |
| `bubble` | A speech bubble with a tail that pops in with an eased scale |
| `queue` | A row of slots holding chips |
| `readout` | A large number or status text |
| `stopwatch` | A dial with coloured arcs, a hand, a crown, a click bounce and a flash |
| `figure` | A friendly figure made of simple shapes whose arm can reach a point |
| `axis` | A time axis with ticks and labels, and an `x(t)` mapping |
| `meter` | A bar that fills |
| `stamp` | A tick or cross that pops in |

Colours come only from tones: `ink`, `ink-2`, `info`, `ok`, `warn`, `stop`, `sunken`, each with a
foreground and a background custom property (`--nx-ok-fg`, `--nx-ok-bg`, ...). `player.css`
defines a light and a dark palette. Scenes never write hex or rgb colours.
The palette uses CSS `light-dark()`, so the player needs a browser from 2024 or later (Chrome 123, Firefox 120, Safari 17.5).

### sfx.js

Sound effects are synthesised with Web Audio, so they ship as code, not files. Cues: `click`,
`pop`, `whoosh`, `tick`, `ding`, `success`, `fail`, `alarm`, `wind`, `thud`. Each cue is a
function `(audioContext, destination, when)`, so the same code plays live and renders offline for
video. The audio context is created on the first click.

## Build tool

`explainer` is a Python command installed with uv.

| Command | Result |
|---|---|
| `explainer new <dir>` | A starter story folder |
| `explainer narrate <dir>` | Records every caption, checks it, writes `narration/` |
| `explainer build <dir> [--fragment]` | `dist/<id>.html`, or a `<figure>` fragment to paste into another page |
| `explainer check <dir>` | Static checks on the story and the built file, and that the player fits common windows |
| `explainer snapshots <dir>` | One PNG per mode and position in `dist/snapshots/`, and a failure on any console error |
| `explainer video <dir> [--mode m] [--fps 30] [--format mp4\|gif]` | An MP4 with the soundtrack, or a silent GIF |
| `explainer models fetch` | Downloads and hash-checks the voice and speech-check models |
| `explainer doctor` | Reports what is installed and how to fix what is missing |

### Narration

1. For each intro step and moment, the spoken text is `say`, or `caption` with `pronounce` and
   the default rules applied (symbols such as ✓ and ✕ are dropped; `200 ms` becomes
   `200 milliseconds`; `%` becomes `percent`; `&` becomes `and`).
2. A clip is reused when the manifest holds the same hash of engine, voice, speed and spoken
   text. Otherwise the voice engine records it.
3. The clip is encoded as mono 48 kbps MP3.
4. A local speech-to-text model transcribes the clip without being shown the expected text. The
   score is the ordered word similarity (difflib ratio over word lists) between the spoken text
   and the transcript after normalising case, punctuation and hyphens. A take passes when the
   score is at least 0.85 and every number in the spoken text appears in the transcript, compared
   as values, so `200` and `two hundred` match. The
   tool keeps the first passing take, up to three takes, and fails when none passes.
5. The transcript's word timestamps are aligned back to the caption's whitespace-separated
   words, so the player can highlight each displayed word.

`narration/manifest.json`:

```json
{
  "engine": "kokoro", "voice": "am_michael", "label": "Michael (Kokoro)", "speed": 1.0,
  "clips": {
    "send": {
      "file": "send.mp3", "key": "<sha256>", "spoken": "The App sends the request.",
      "duration": 2.41, "score": 0.97,
      "words": [[0.00, 0.12], [0.12, 0.40], [0.40, 0.81], [0.81, 1.02], [1.02, 1.60]]
    }
  }
}
```

`words[i]` is the `[start, end]` in seconds of the caption's i-th whitespace-separated word.

Voice engines are plug-ins with one function, `synthesize(text, voice, speed) -> (samples,
sample_rate)`. Built in: `kokoro` (in-process, default) and `http` (any local server that speaks
the OpenAI `/v1/audio/speech` API).

### Built file

One HTML file with a Content-Security-Policy meta tag that allows only inline scripts and
styles and `data:` media, images and fonts. The story JSON and the narration map sit in
`<script type="application/json">` tags with `</` escaped. Audio is `data:audio/mpeg;base64`.
The bundle contains no `http:` or `https:` URL in any `src`, `href` of a stylesheet, `fetch`,
`XMLHttpRequest`, `WebSocket` or `import()`. Ordinary `<a href>` links are allowed.
